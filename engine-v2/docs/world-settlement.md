# World settlement prototype

The internal settlement service advances up to 1,000 event instants per transaction using server time. It locks inventory bean rows, consumes in memory during simulation and writes the remaining quantities, aggregates kill XP/gold and persists pending loot in the same transaction as the battle state. A failed transaction rolls back all changes. Pending loot is not yet granted to the bag: a separate claim transaction is needed to preserve the legacy loot summary and full-bag behavior. The caller must supply trusted context and reward calculation; those adapters and integration tests remain pending. Boss finalization and daily ledger integration remain pending. Aggregating XP per batch can differ from legacy level-dependent rewards; this must be resolved before release. No HTTP endpoint.
